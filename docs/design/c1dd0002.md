# c1dd0002 — the parser origami

**Status:** DESIGN ONLY. No code, nothing on chain. This document designs
how a quipu reader unfolds from a small hardcoded seed into a full
per-version parser by reading the on-chain estandarte, and what the v0.2
standard adds.

**Revised 2026-07-17** after the full-corpus encoding audit and its
interactive triage. This revision absorbs: the type-atom algebra (§7.1),
the rebirth of the v1 registry format (§7.1), the abolition of certainty
markers (§7.3), the re-engineering criterion (§2), uniform honest reading
(§5), and `network.py` — a fourth typed-var clone the previous draft
missed (§7.5). Two of the previous draft's open questions are answered
and one is dead (§10). The constitution gains the **genesis fan-out** in
the same pass — despot · amend · commentary, the burn ladder
([c1dd0000.md](c1dd0000.md), Articles V–VII).

Citations resolve against the working tree and are collected in
[Appendix A](#appendix-a--grounding-table). Where two copies of a codec
exist, citations name the **`canonical/`** copy.

## 0. What this is

A design draft — freely rewritten until something is inscribed (the
healing model governs chain data, not working documents). It supersedes
the original "v0.2 format bump" draft, the interim "born-skippable
registry" model, and the 2026-07-1x celestial-only §7 scope. The model:
**each version is its own self-declaring standard.**

---

## 1. The origami

A protocol that inscribes its own registry on chain can teach a reader to
parse it. The estandarte (type `0xee`) is that registry — the
constitutional quipu that documents the type-byte vocabulary, each type's
enum dimensions, flags, statuses, and conventions. Today it works at the
level of an **enum dictionary**: it names the bytes hardcoded parsers
already extract. The horizon is a **grammar**: descriptions rich enough
that a reader parses a type it has no code for.

The organizing image: parsing unfolds like origami. A reader starts with
a small hardcoded **seed** and performs **folds** by reading the chain —
resolve the registry, load the type table, later load field grammars. The
unfolding happens *within a version*; the version boundary is a clean
cut, not a fold. v0.2 does not build the grammar — but it now supplies
the grammar's **alphabet** (the type-atoms, §7.1), so the later folds
extend the dictionary instead of replacing it.

---

## 2. The version is the standard

The spine, and the whole simplification: **each version is a
self-contained standard.**

- A version's **estandarte** — type `0xee`, its header carrying that
  version — declares that version's rules by **inheriting the prior
  version and layering only its delta**: it reuses every unchanged type
  and overrides only what the bump touches, over a `parent_txid` chain
  (leaf-wins) rooted in the prior standard and signed by ACH (§3).
  `c1dd0001`'s estandarte declares v1 from scratch; `c1dd0002`'s inherits
  v1 and states only its delta.
- The node **buckets by version.** `dogecoin_qpu` filters the 2-byte
  `c1dd` magic, reads the version at bytes 2–3, and passes both through
  untouched — it is version-blind and payload-opaque by design (audited
  2026-07-16: `src/rpc/quipu.cpp` — **zero node changes** for any
  version bump, ever).
- **One mechanism, two grains.** The amendment chain (`parent_txid`,
  leaf-wins — `resolve_estandarte_chain`) does all the composing. A
  same-version amendment grows *content*; a version-bump amendment
  increments the version and may extend the registry *format* — but it
  is still only a delta layered on its parent. The operational policy
  for the two grains is [healing.md](healing.md).

### The re-engineering criterion

*(ratified 2026-07-17)* — **A version bump is the opportunity to shed
the engineering that existed only to stay parseable against old
inscriptions.** Old blobs keep their parser forever, selected by their
version byte; the new layout owes the old one nothing and is designed
clean, not additive-patched. In law form:

> v1 readers exist to keep every inscribed blob legible, warts included,
> frozen. v2 layouts are designed as if the protocol were being written
> today — because within the new version, it is.

First applications: v2 celestial has **one** date mechanism (§7.4) — the
legacy per-point pmeta time slot is not part of the v2 grammar at all;
image's lenient-title heuristics and book's header/body split-guess stay
v1-only forgiveness, never carried forward.

### Scope of a version

**v2 is a whole standard, open to any type that has a reason; types
without one keep their v1 wire.** New inscriptions of untouched types
(text, image, book, latex, …) continue to emit `c1dd0001` — a
mixed-version corpus is correct by construction, and the node routes
each blob to its standard. But nothing forecloses a v2 layout for any
type when a reason arrives (a text subtype dimension, say): it is
mechanically one more delta entry in the v2 estandarte, one more
registration. The version's meaning is uniform; participation is
per-type and reasoned.

### Worked example: `0x0c`

`0x0c` (cert-precursor) sits deprecated in the v1 registry from birth —
the honest record of the first failed inscription, readable forever. A
reader meeting a `c1dd0001`/`0x0c` blob resolves it against v1 and
labels it honestly. Because each version is a fresh namespace, `(v2,
0x0c)` is simply unbound — reclaimable if ever wanted, while the v1
record stands.

## 3. The seed

The irreducible kernel a reader carries as code — the part of the wire no
estandarte can describe, because the reader needs it to *find and trust*
the estandarte. Four elements, specified concretely in
[c1dd0000.md](c1dd0000.md):

1. **The envelope grammar.** Six bytes, hardcoded forever: 2-byte magic
   `c1dd`, u16-BE version at bytes 2–3, type, tone. Codec:
   `canonical/envelope.py` (built 2026-07-11; fixes the literal-magic
   reject and the short-header IndexError).
2. **The estandarte body format, inherited across versions.** A v2
   reader is a v1 reader plus v2's format delta, never a fresh parser.
   Each estandarte also self-declares its format via the metacircular
   `0xee` self-entry, for far-future reconstruction (§6).
3. **The trust anchor.** The ACH 3-of-3. The seed carries the slot empty
   until the ceremony.
4. **The tip rule.** From the constitution root's genesis tag and its
   fan-out: **the despot check first** (latent / exercised / burned,
   c1dd0000 Article VII), then the amend thread for the constitution's
   current text, then legislation — v1 anchored by signed `parent_txid`,
   v1 onward walked by per-root cords — with the signed scan as
   fallback. Commentary is never consulted for law.

**Audit state (2026-07-16).** The estandarte trio (constitution /
registry_v1 / estandarte) parses versions through `envelope.py`; **26 of
28 other readers still literal-compare the 4-byte `c1dd0001`** and
reject any other version as bad magic, and the client
(`invisible/spectra/decode.py`) checks no magic at all. One live defect:
`colegio/colegio/envelope.py:34` — the envelope copy the client actually
imports — does a strict `MAGIC + VERSION` 4-byte compare and would
reject every v2 quipu today. Version dispatch (§7.2) is v0.2's first
plumbing job.

## 4. The folds

The reader's capabilities, in the order they unfold — within a version.

| # | Fold | What the reader gains | When |
|---|---|---|---|
| 1 | **The seed** | Find, read, trust the version's estandarte | Hardcoded |
| 2 | **Resolve the chain** | The merged registry, leaf-wins over the anchored chain | Exists today |
| 3 | **The type table** | For each type: name, status, dimensions (now atom-typed), flags | v0.2 |
| 4 | **The field grammar** | Body layouts as data: parse types with no code | v0.3+ (§8) |

The previous draft's fold 5 (the variable union) is no longer separate:
**declaring the atom table on chain in the v2 estandarte *is* the
variable-union statement** (§7.1). The union's four working-tree copies
and their divergences are retired by the unification (§7.5).

## 5. Packed bodies, honest reading

Data bodies stay **flat and packed** — a date is 9 bytes (§7.3), a ref
is 32, no per-field length prefixes, every OP_RETURN byte paid for. The
registry carries the descriptions; the wire carries the data.

**Uniform strictness, gated on legibility** *(ratified 2026-07-17)*.
Until a standard is inscribed there is nothing magical about legacy
reader behavior — the healing model protects inscribed bytes and
inscribed law, not working-tree code. So there is **no per-version
strictness dispatch and no lenient shim**. One policy, everywhere:

- **Unknown vkind → raise.** An unknown atom byte means the value's
  *width* is unknown — nothing after it in the block can be read. The
  three silent-`break` clones (etymology, network, client) die in the
  unification (§7.5). Never silently drop.
- **Undecodable header text → raise.** The ~13 readers that decode
  titles with `errors="replace"` silently corrupt malformed UTF-8 into
  `�`. They stop. A broken-quipu marker **is** legible — it is the
  honest rendering of what is there; nothing published ever promised the
  scar.
- **Closed enum vs open atom — declared, not tribal.** Every enum-ish
  byte is classified in the registry: a **closed enum** (the values list
  is the law; unknown = malformed = raise) or an **open u8 atom with an
  advisory naming table** (tone: fixed width regardless of value,
  semantics advisory, pass through labeled). The registry says which,
  on chain, per dimension. This also fixes the one accidental coerce:
  the estandarte's own reader validates `status` on build but not on
  read — it gains the check (no inscribed history to respect).
- **Containment stays the view's job.** A gallery catches the raise at
  the figure boundary and shows the broken marker; error surfaces,
  nothing dropped, the gallery survives.

**The empirical gate:** all 65 corpus quipu must parse byte-exact and
title-exact before and after — `test_corpus_regression.py` (39 canonical
bodies, strict) + `colegio/tests/test_corpus_groundtruth.py` (65-quipu
cross-implementation byte-identity; currently skipping on a missing
`qrcode` dep in the colegio env — **un-skip it before any change**).
Legibility of the data is the constraint; everything else is ours to
fix.

---

## 6. The payoff

A reader in 2126, holding the seed and a copy of the chain: it filters
`c1dd`, buckets by version, checks the despot, walks the legislation
thread rooted at and signed by the ACH anchor, and resolves the registry
leaf-wins. The type table labels every blob by `(version, type)`, and —
because dimensions are atom-typed — states every declared field's width
as data, not prose. Post-v0.3, field grammars let it *parse* bodies
whose reference code never survived. Contingent on the anchor: without
it the 2126 reader cannot tell the constitution from a forgery that
cites it.

## 7. v0.2 — the second standard

v0.1 formats are frozen and idiosyncratic; we do not grow them with
piecemeal additive kinds. v0.2 is a coherent new standard, declared by
its own estandarte and dispatched by version. Eight items:

### 7.1 The algebra — type-atoms and the vkind'd dimension

The wire already invented the atoms: `VAR_TEXT`/`VAR_REF`/`VAR_DATE`
(`0x00`/`0x01`/`0x02`) are byte-identical across all four more-block
codecs, and `VAR_TEXT` already carries a u16 length. v0.2 promotes that
namespace to **the protocol's single set of type-atoms** and completes
it:

| byte | atom | wire form | status |
|---|---|---|---|
| 0x00 | text | u16-BE len + UTF-8 | exists |
| 0x01 | ref | 32-byte txid | exists |
| 0x02 | date | precision:u8 · jd:f64-BE (9 B, §7.3) | exists; v2 layout |
| 0x03 | u8 | 1 byte | new |
| 0x04 | u16 | 2 bytes BE | new |
| 0x05 | u32 | 4 bytes BE | new |
| 0x06 | f32 | 4 bytes BE | new |
| 0x07 | f64 | 8 bytes BE | new |
| 0x08 | bytes | u16-BE len + raw | new |

One namespace, two uses: **operational** (a more-block tags each value
with its atom — already true) and **descriptive** (the registry cites an
atom to state a field's shape — the new part). Width is `width(atom)`,
a total function, never prose. Future atoms ride future version bumps —
vocabulary, not descriptor-language, so no hard fork (c1dd0000, three
tiers).

**The dimension entry gains one byte:**

```
name · desc · vkind:1 · value_count:1 · values( value:width(vkind) · name · desc )
```

Cert's subtype declares `vkind=0x04` and its values encode as 2 bytes —
the docstring hedge ("one 16-bit dimension or two 8-bit") dies with a
definitive answer: **one 16-bit dimension**. Old open Q4, resolved. A
grammar-fold reader computes the offset instead of guessing it.

**Placement: rebirth of v1** *(decided 2026-07-16)*. Nothing is
inscribed, so the vkind byte enters the registry format **from birth** —
the v1 registry golden regenerates as a deliberate reviewed amendment,
and the inscribed v1 never carries a machine-false width claim. The
constitution golden regenerates in the same pass for a different reason
(the preamble/safety conventions, c1dd0000 Articles VI–VII); its zero-dim
self-entry means the vkind byte itself should not move v0 bytes —
verified at build. **Atoms only** *(decided 2026-07-16)*: no seeded
field-grammar descriptor; combinators are v0.3 work (§8). Old open Q2,
resolved.

The u8 *counts* (max 255 types/values per blob) are a non-issue: the
amendment chain paginates — a second leaf carries the rest.

### 7.2 Version dispatch

Readers parse bytes 2–3 as u16-BE and select the standard *before*
parsing a body, replacing the literal `b"\xc1\xdd\x00\x01"` comparison
in the ~26 readers that still carry it. Three named repairs:

- `colegio/colegio/envelope.py` — retire the 4-byte `MAGIC + VERSION`
  compare (the copy the invisible client imports; today it would reject
  every v2 quipu). Align with `canonical/envelope.py`.
- `invisible/spectra/decode.py` — read the version at the one dispatch
  point and route `(version, type)`; today it dispatches on `hdr[4]`
  alone and never looks at bytes 2–3.
- Per-type readers: the **v2-touched family** (celestial + estandarte)
  parses the version and dispatches. Untouched v1 types keep their
  4-byte guard — for a type whose only wire is v1, the literal is
  *correct*, and each type adopts version dispatch at its own future
  bump (the A2 resolution). The client's whole-version honesty above is
  what protects them meanwhile: an unimplemented version is reported
  whole before any per-type reader sees it.

### 7.3 `VAR_DATE` v2 — precision, and nothing else

Same atom `0x02`; the blob version disambiguates the layout:

- **v1 value** (frozen): `jd:f64-be` — 8 bytes.
- **v2 value**: `precision:u8 · jd:f64-be` — **9 bytes**.

```
precision:  0x00 unspecified · 0x01 exact · 0x02 day · 0x03 month · 0x04 year
jd:         IEEE-754 f64 big-endian Julian Day (noon convention, BCE-safe)
```

Precision is **structural** — the granularity of the datum, what it
*is*. "1519" is a year; a renderer that paints it as noon-July-1
fabricates specificity the datum never had. Auto-derived:
`encode_journeys.date_to_jd` already parses the source string, so
granularity falls out (`"1519"`→year, `"1519-04"`→month, …), and the
renderer widens the marker instead of faking noon.

**Certainty markers are abolished** *(ratified 2026-07-17: "against the
ethos of the project")*. The previous draft's certainty byte
(attested/circa/disputed/legendary) is stricken; no certainty vocabulary
exists anywhere in the standard. The telling does not footnote itself;
the mythic frame lives in the quipu's kind and register, not in a
per-date epistemic byte. `date_confidence` is retired in favor of
**nothing** — scholarly hedges stay off-chain in `working/journeys/`.
Etymology's free-text `certainty` key is simply not among v2's reserved
keys. Old open Q3 (packed vs separate certainty) is dead. One edge
remains open (§10): network's `NTYPE_UNCERTAIN = 0x04`.

### 7.4 One date mechanism; dates are earth-only

The re-engineering criterion applied to celestial dates. v1 carries two
mechanisms — the legacy per-point pmeta time slot (earth-gated) and the
more-block `VAR_DATE` (ungated: the side door — a star could carry a
date var). v0.2 resolves the incoherence by **closing**, not lifting
*(Anthony, 2026-07-17: "I don't think we need dates on stars — we can
always define that subtype if it's needed")*:

- **The v2 celestial grammar has exactly one date mechanism**: the typed
  var (`0x02`, 9 bytes), legal on **earth points only**. The pmeta time
  slot is not part of the v2 layout — it lives on in the v1 parser,
  which is the only place it is needed.
- **The side door seals as a defect, not as law.** Readers refuse a
  date var on a star-tagged point uniformly; the empirical gate is the
  corpus (no inscribed blob carries one — verified by the regression;
  the synthetic test that exercised the hole now asserts the raise).
- **Star-time stays reserved** — the three self-describing gate sites
  keep their reservation, indefinitely and honestly. If a dated sky is
  ever truly needed, it enters as its own declared subtype/version with
  its own render semantics, not as a leak.
- **The heavens enter time through the event.** A dated event on earth
  *references* a star; the star stays timeless on the celestial sphere.
  Both bridges already exist and need no new format: within a mixed
  figure, a line connects the dated earth point to the star (lines are
  kind-unrestricted); across quipu, the earth point's more-block carries
  a `date` var and a `ref` var citing the star figure. Time lives on
  earth; the sphere is eternal; the reference is the bridge.

### 7.5 Typed-var unification — four clones, one strict codec

The previous draft counted three copies; the audit found **four**:
`canonical/celestial.py`, `etymology.py`, `network.py:184` ("Faithful
clone of etymology"), and the client's
`invisible/spectra/decode.py:104`. One shared more-block codec replaces
all four, with the uniform strict policy of §5 (the celestial copy's
raise wins; the three silent `break`s die). `network.py` also sheds its
builder's vkind-lock (`VAR_DATE` becomes emittable on network nodes —
today it is decodable but unbuildable). The v2 estandarte's atom-table
declaration is the single on-chain statement of the union.

### 7.6 Ratified widths

- **Coordinates stay f32** *(decided 2026-07-16)* — lat/lng, RA/dec,
  and the etymology/network spans. Quantization documented honestly in
  the v2 registry desc: **~2.4 m on the ground, ~0.08 arcsec on the
  sky**. Lossy by decision, not by default. An astrometric need someday
  becomes its own kind carrying f64 atoms — the algebra keeps that door
  open forever.
- **Reserved slots stay reserved** *(decided 2026-07-17)*: the
  etymology/network grouped+meta header bytes stay MUST-be-0; file.py's
  seven flag bits stay reserved. Slots don't expire; activating them
  ahead of a live need is memorializing a hypothetical.

### 7.7 Strings are atoms — the v2 convention

Every v1 length-prefixed string (title, name, caption, dim name, desc)
is a hard u8 cap, and the pipe-delimited types cannot contain `|` in a
title at all. The v2 convention: **formats authored or re-formatted
under v2 use atoms for their strings** (the text atom's u16 length).
Applied to the types v0.2 touches; every other type inherits the
convention at its own future bump, for its own reasons. No gratuitous
migration.

### 7.8 Ride-along repairs (code-work, no wire change)

- `book.py`: validate the `BODY_VERSION` byte it already writes and
  echoes (today a future 0x02 body would silently misparse as v1);
  retire the header/body split-guess.
- `dancer.py`: builders raise on overflow instead of silently wrapping
  with `& 255` (`narc = len(edges) & 255` corrupts, not just truncates).
- `genealogy_to_tikz.py`: the route guard becomes a real `ValueError`
  (an `assert` evaporates under `python -O`).
- Stale docstrings: `sound.py` header-length 17-vs-16; `cert.py` subtype
  list missing the live `0x03`.

**Registration surface:**

- `canonical/estandarte.py` — vkind'd dimension codec; author v1
  (rebirth) + v2 registries; status read-validation; version dispatch.
- `canonical/envelope.py` — unchanged (already correct).
- `canonical/celestial.py`, `etymology.py`, `network.py` — shared
  typed-var codec; v2 layouts (one date mechanism, star-time); version
  threading.
- `colegio/colegio/envelope.py` — version-aware reconciliation.
- `invisible/spectra/decode.py` + `view.py` — version dispatch;
  precision-aware markers; the client's clone of the more-block codec
  retired.
- `working/journeys/encode_journeys.py` — emit `VAR_DATE` v2 (precision
  auto-derived); `date_confidence` dropped.
- `canonical/constitution.py` + `quipu_preflight.py` — the genesis-tag
  slot and fan-out slots (despot / amend / commentary), and the ceremony
  gates: fan-out shape (three outputs, ordinal, ACH, no OP_RETURN),
  succession agreement, exercise-vs-burn physics (c1dd0000 Articles
  V–VII).
- **The tag quarantine** (`quipu_preflight.py` + console) — intact-tag
  set derived via `classify_root_outputs`, never hand-kept; preflight
  refuses any tx spending an intact tag unless it is a declared act
  passing that act's gate; tag addresses never shared with funding. An
  accidental sweep is a constitutional act by mistake.
- **Gates** — `tests/golden/*` both regenerate (reviewed);
  `test_corpus_regression.py` + `test_corpus_groundtruth.py` (un-skip
  first) prove the v1 corpus byte-exact throughout; the three estandarte
  test files extend for vkind + tags.

**Deliberately out of scope:** the encrypted-wire fork
(`colegio_tools.py` vs `canonical/encrypted.py` cross-misparse,
unauthenticated AES-CBC) — real, version-independent bug-work with
key-bearing blast radius; its own session. The node: zero changes.

## 8. v0.3+ — fold parsing in

Deliberately thin. The grammar fold: per-`(version, type)` field-grammar
descriptors in the registry, rich enough that a seed-only reader parses
a body with no type-specific code. The atoms (§7.1) are the grammar's
terminal symbols; what v0.3 adds is the **combinators** — `seq`,
`rep(count-field)`, `opt(flag/predicate)`, `union(tag-field)` — and the
more-block is already the union combinator in the wild. Design against
the simplest real type first (text, `0x00`) and generalize only from a
working proof.

### The per-type trigger (decided 2026-07-12)

The registry stays a monolith per version until the grammar fold gives
bodies a schema pin to carry. It decomposes into per-type registries at
exactly one moment: the first inscription that pins the grammar it was
authored against. At that moment the registry family becomes three
roles: **constitution** (`c1dd0000ee`, the seed) · **per-type
legislation** (one `0xee` chain per type) · **manifest** (the
corpus/set quipu, snapshots "the protocol as of block N"; deferred until
then).

### Horizon, not scope — the code type (noted 2026-07-17)

Beyond the grammar fold: a type whose body is executable — capability
itself as chain content, blossoming to every deployed reader without a
release. The asymmetry is conserved, not dissolved: the frozen layer
relocates from the descriptor language to the **sandbox contract**
(bytes in, structure out, no IO, resource-capped) — small and
freezable; the language behind it is deliberately not the frozen
object (not Python to ride). Governance comes free: code entries are
legislation — signed lineage, status, deprecation, the despot while it
lives. Doctrine if ever taken: **describe for eternity, execute for
now** — decoding stays grammar-as-data forever; code may carry only
the live layer (render, behavior). The record never needs execution.

### Invariant — the version's locus (decided 2026-07-12)

**Never per-type registries AND a global-currency version stamp at the
same time.** Bytes 2–3 are constitutional and never vacate; what must
not split is what they track. The split lands as one final version bump
whose standard says "bodies pin their type-registry leaf"; bytes 2–3
freeze at that era-version, and "the protocol is at vN" becomes a
statement the manifest makes. Holding both axes at once pays the
monolith's touch-everything tax plus per-type's resolution overhead —
the two designs' costs with neither's benefit.
